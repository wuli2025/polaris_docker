Polaris · 互联层 V2

隔空同屏 + 应用直投

V1 让手机与电脑同看一份文件。V2 再进一步:把电脑当服务器, 手机跑一个空壳网页端,直接使用电脑上带后端的真实应用 —— 比远程桌面清晰、省流、可选可搜、触摸原生。这一页你正在 app 里读, 手机横过来就自动切成电脑版式。

1两个能力,一条底座

隔空同屏 · Beam

投一个「文件」

主机把文件打包成一页自包含网页,两端渲染同一份 HTML,滚动/指点/字号实时同步。 看报告、过 PPT、一起圈重点用它。横屏即电脑版式。

应用直投 · V2 新增

投一个「应用」

主机把它本机在跑的 HTTP 应用反代给手机。手机上操作的是真实应用本体, 计算全在电脑。断线重连不丢状态 —— 状态在电脑上的应用里,手机只是视图。

两者共用同一条底座:已有的 iroh P2P 隧道(打洞 + relay 兜底 + mDNS)。 都不要求同一 WiFi,4G 也能用。

2比远程桌面好在哪

🖥️ 远程桌面(投像素)

  • 带宽 Mbps 级,4G 下糊成一团
  • 文字不可选、不可搜、不可复制
  • 触摸要模拟成鼠标,别扭
  • 手机屏比例和电脑对不上,黑边或裁切
  • 断线 = 画面卡死,重连从头来

📡 应用直投(投 HTTP 报文)

  • KB 级流量,4G 顺滑
  • 原生 DOM,文字可选可搜可复制
  • 触摸就是触摸,输入法原生
  • 页面按手机屏自适应,横屏即电脑版式
  • 断线重连不丢状态(状态在电脑上)

3怎么用应用直投

电脑侧:发布

  1. 互联 → 设备与授权 → 应用直投 → 扫描本机应用。
  2. 在扫到的端口里点发布(自动起短名)。
  3. 「在本机浏览器打开」可先自己验证通不通。

手机侧:使用

  1. 抽屉 → 应用 → 点开已发布的应用。
  2. 全屏使用;横过来自动进电脑版式 + 沉浸。
  3. 顶栏细把手唤回工具条,可强制横屏 / 系统浏览器打开。
什么能投、什么不能投。 只能投开了 TCP HTTP 端口的应用:开发服务器(Vite / Next / Flask / Streamlit…)、 带内置 HTTP 后端或 sidecar 的桌面应用。 Tauri / Electron 的生产包默认走 tauri:// / file:// 自定义协议,不开 TCP 端口 —— 投不了。 想投那种应用,开它的 dev server(如 npm run dev)再扫端口; 否则只能退回画面流,那就是远程桌面。

4它是怎么做到的

环节做法
反向代理 裸 TCP 说 HTTP/1.1,不引 HTTP 客户端。请求头改写后转发,响应按 chunked / content-length / EOF 三种成帧方式流式回传 —— SSE、大文件、长轮询都不缓死。已有真 HTTP 端到端测试钉住成帧正确性。
WebSocket / HMR 拿 hyper 的 OnUpgrade,握手成 101 后 copy_bidirectional 裸转字节。Vite 热更新、Socket.IO、应用自己的实时推送照常 —— 远程桌面给不了这个。
凭据(关键) 手机壳是 WebView,应用在 iframe 里算第三方,安卓默认拦第三方 cookie。所以真正的凭据是路径里的一次性会话票据 /x/{sid}/;绝对路径的子资源(/assets/x.js)靠服务端从 Referer 认回会话。owner 令牌绝不进任何 URL。
粘性回退 应用页面里的绝对路径没有 /app/{slug} 前缀,由 cookie 或 Referer 里的会话票据认回它属于哪个应用。不改应用一行 HTML,零侵入。

5安全边界

① 会话票据是能力票

每个 /x/{sid}/ 只对一个应用有效,12 小时过期,主机重启即全部作废(会话只在内存)。 owner 令牌只在换票据的一瞬用一次,不出现在 URL / Referer 里。

② owner 闸 + 自噬防护

开会话要 owner 权限;发布清单拒绝端口 0 与「polaris 自己的端口」, 避免请求转给自己成环。/api /ws 永远不被代理接管。

③ 票据不外泄给应用

转发给上游前,Cookie 头里 polaris 自己的项被摘掉 —— 被代理的应用看不到会话票据。

④ 只发你信得过的

发布出去的应用与 polaris 同源。它拿不到 /api(那只认 Bearer/?token=,不认 cookie), 但仍应只发布自己信任的本机应用。

6GitHub 调研:为什么不引第三方

项目取舍
iroh / dumbpipe 已在用隧道就是 dumbpipe 式 TCP↔QUIC 双向拷贝,应用直投直接跑在上面,零改动。
iroh-examples 的 http-over-dumbpipe 同思路官方示例就是「把 HTTP 转进 dumbpipe 暴露本机服务」,验证了做法正确。我们在应用层做反代以便加鉴权/会话,而非裸转。
iroh-h3 / web-transport-iroh 没引在 iroh 上跑 HTTP/3 很诱人,但现有数据面已是 axum + 隧道透传、能跑完整 HTTP;换 h3 收益是延迟边角料,代价是重写整条数据面。
nginx / caddy 反代 没引要的功能只是「TCP↔TCP + 会话闸」,自己写 ~600 行、零外部进程,还能复用 polaris 的 owner 鉴权。引一个反代进程反而多一个要管的东西。
iroh-docs 留作后手要做「两端同时编辑同一份文档」时用它的 CRDT,别自己写 OT。

结论:网络层不用再引任何东西,隧道已经够;反代自己写最省心。
