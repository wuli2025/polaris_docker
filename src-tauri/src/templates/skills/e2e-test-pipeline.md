# 自动化测试流水线（探索→用例→脚本→维护）

给一个真实应用从零建 E2E 自动化测试，或往存量套件补测试。四段式流水线，段间有人工评审门。综合 Playwright 生产实践（TestDino 等）。

## 第 1 段 · 探索
- 用浏览器自动化实际逛一遍应用：登录、主要业务流、各用户角色能见什么。
- 产出 `app.context.md`：业务流清单、用户角色与权限、鉴权模式、关键页面结构。后面各段都读它，不重复探索。

## 第 2 段 · 用例设计（出给用户评审）
- 基于探索文档产出测试场景表：前置条件 / 步骤 / 预期结果 / 优先级。
- 覆盖优先级：核心业务流 happy path → 权限边界（谁不该看到什么）→ 错误路径 → 边界值。
- **人工评审门**：用户勾选批准的用例才进第 3 段。

## 第 3 段 · 脚本化
- Page Object Model：每页一个小 PO 文件（保持小，别造出一次读爆上下文的巨物），用例引用 PO。
- 定位强制 `getByRole` / `getByLabel` 语义定位；断言用 auto-waiting 的 `expect`，禁 sleep。
- 鉴权用 `storageState` 复用登录态；多角色在 global setup 预生成各角色的 storageState。
- 有数据依赖的用例用 `test.describe.serial()` 串行，其余默认并行。
- 每条脚本写完实际跑绿一遍才算交付。

## 第 4 段 · 维护
- 分析失败：按错误信息分组，区分「应用 bug / 测试脆弱 / 环境问题」。
- **只提议修复，不自动改测试**——尤其权限类断言，静默改掉会掩盖真实越权 bug。判断是 bug 就升级成 bug 报告。

## 红线
- 段间用文件交接，可随时暂停人工修改：机器提议，人批准。
