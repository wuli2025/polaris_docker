# 项目skill（开发七纪律）

做项目/写代码时自动生效。不教怎么做，只圈行为红线——按当前任务取用对应小节。

## 1. 先读懂项目
- 动手前先摸清：入口、分层、要改的东西现状、有无同类实现可照抄。
- 改之前先搜一遍：谁在调用、类似逻辑还在哪几处。说不出「影响哪些文件」就还没读够。
- 跟随项目既有约定（命名/错误处理/目录归属），不另起炉灶。

## 2. 先想放哪层
- 写第一行代码前先回答：这段逻辑属于哪一层？项目里同类放哪？就放那儿。
- 要在 3 个以上不相干地方各加一坨 → 大概率放错层了，停下重想。
- 不为「以后可能用到」提前抽象；依赖方向只准往下；拿不准选删起来最容易的方案。

## 3. 代码审查
- 按三条线各过一遍：**安全**（注入/越权/机密泄漏）、**性能**（循环里的 IO、N+1、无界增长）、**边界**（空值/超长/并发/失败路径）。
- 每个问题给 `file:line` + 一句话后果，分必改/可选；说不出「什么输入触发什么坏结果」的不算问题。
- 被审时先复现再改，不盲从也不嘴硬。

## 4. 抓虫
- 铁律：**复现 → 定位 → 证据 → 修复 → 回归**，一步不跳。复现不了就先搞复现，不许盲修。
- 修之前必须一句话说清「因为 X 所以 Y」；日志报在 A 不代表错在 A。
- 只修根因那一处；吞异常/调大超时这类压症状不算修；修完跑复现路径验证。

## 5. 补真测试
- 只写拦得住真 bug 的测试：边界值/错误路径/并发优先，happy path 一条就够；断言具体值。
- 实际跑绿一遍才算写完，没跑过就如实说；不为覆盖率凑数，难测代码先说出来。

## 6. 迁移/重构先拆阶段
- 一口气改不完的活，动手前先列：分几阶段、每阶段结束系统仍能跑、最大 2-3 个风险、怎么回滚。
- 每阶段独立可验证可回退；新旧共存期明确权威数据源；列「明确不做」清单防失控。

## 7. 发版前查全
- 逐项过完才许发：构建真跑通、测试绿、`git status` 干净、版本号一致、changelog 更新、密钥没进包。
- 每项要看到命令真实输出，「应该没问题」不算过；有一项红就停，不许「先发了再补」。
- 发完做最小冒烟验证（装得上/起得来/核心路径点一遍）才算发完。
